# T0.3 — knigavuhe.org audio discovery (spike)

Date: 2026-11-05. Scope: investigation only — no app code/tests were modified.

## TL;DR

Audio files **can be reliably extracted**. The book page embeds the entire playlist as
JSON inside an inline `<script>` blob (`new BookPlayer(<book_id>, [...])`). Each track
URL has the form:

```
https://s1.knigavuhe.org/1/audio/{book_id}/{md5}/{track_no}.mp3?{v}
```

The files are plain MP3 served over HTTPS and download freely — **no cookies, Referer,
session token, or signature** are required (`?{v}` is ignored by the server; Range
requests are supported). The only caveat is that URLs appear to be rotated periodically
(see "URL rotation" below), so the app should pull URLs from a fresh book-page fetch at
download time.

## 1. Search page

`https://knigavuhe.org/search/?q=<uriencoded>` is **server-rendered HTML** (no JS needed).
Pagination is classic server-side: `/search/?q=...&page=2` (the "Показать ещё" button is
progressive enhancement over the same `page` param).

Result cards are `<div class="bookkitem">` elements. For each card:

| field       | CSS selector                                              | notes |
|-------------|-----------------------------------------------------------|-------|
| book slug   | `a.bookkitem_cover[href]` → `/book/<slug>/`               | slug may or may not start with the numeric id<br>(`285-master-i-margarita-1` vs `master-i-margarita-7`) |
| cover       | `a.bookkitem_cover img.bookkitem_cover_img[src]`          | host varies `s4/s5/s9.knigavuhe.org`, path `/1/covers/<id>/<x>-1.jpg?v=N`; `alt` = title |
| title       | `div.bookkitem_name a.bookkitem_name`                     | may contain `<span class="highlight_keyword">` |
| author      | `div.bookkitem_author a[href^="/author/"]`                | label `span.bookkitem_author_label` = "автор" |
| reader(s)   | `div.bookkitem_meta_block` with `span.bookkitem_icon.-reader`, then `a[href^="/reader/"]` | label "Читает"/"Читают" |
| duration    | `span.bookkitem_meta_time`                                | e.g. `16 часов 39 минут`, `13 часов`, `11 минут` |
| genre       | `div.bookkitem_genre a[href^="/genre/"]`                  | |
| views / likes / comments | `div.bookkitem_meta_block` icons `-views`, `-likes`, `-comments` | |

Some cards have no duration (e.g. the "Литрес" promo-embed notebook) — treat all fields
as optional.

## 2. Book page — where the audio lives

`https://knigavuhe.org/book/<slug>/` is also server-rendered. Answer to the
server-rendered / JS-blob / XHR question: **(b) embedded in an inline JS script blob** —
plus a redundant server-rendered playlist `<div>` that does **not** contain URLs.

Two places contain playback data:

1. **Playlist HTML (no URLs).** `div#player_playlist` is emitted server-side and contains
   one `div.book_playlist_item` per track (`id="playlist_item<id>"`, `.book_playlist_item_time`
   = mm:ss, `.book_playlist_item_name` = 0001…). Useful for track counts/titles but there
   are **no audio URLs here**.
2. **Inline script (authoritative URLs).** Near the bottom of the page, inside a
   `<script>` block:

   ```js
   var player = new BookPlayer(285, [
     {"id":1951646,"title":"0001",
      "url":"https:\/\/s1.knigavuhe.org\/1\/audio\/285\/7ed0707fe3d621de3993505eb3f58b42\/0001.mp3?1",
      "player_data":{
         "title":"Мастер и Маргарита","cover":"https:\/\/s5.knigavuhe.org\/1\/covers\/285\/7-3.jpg?v=2",
         "cover_type":"image\/jpeg","authors":"Михаил Булгаков","readers":"Кира Серова",
         "series":null,"url_refresh":true,"url_refresh_at":1793947978,"url_refresh_in":221130},
      "error":0,"duration":300,"duration_float":300.46},
     ...
   ]);
   ```

   Each item: `id` (track/node id), `title` (`0001`…), `url`, `player_data`
   (book title/authors/readers/cover/series + url-refresh metadata), `error`, `duration`
   (seconds, int), `duration_float`.

The book id is available redundantly via `cur.book = {"id":285,"name":"…","genre_id":13,…}`
in the same script. There is **no separate XHR/JSON endpoint** required to get the URLs.

### Exact audio file URL pattern

```
https://s{digit}.knigavuhe.org/1/audio/{book_id}/{md5_hex32}/{track_no}.mp3?{v}
```

- `{digit}` — host shard (`s1` for audio; `<link rel="preconnect" href="https://s1.knigavuhe.org">`).
- `{book_id}` — numeric id (`285`).
- `{md5_hex32}` — 32-char lower-hex per-file path segment (constant content hash, not per-session).
- `{track_no}` — 4-digit zero-padded `0001`…`0197`, matches playlist order.
- `{v}` — small int (`1`) cache-busting query; the server **ignores** it (see §3).
- Extension: **mp3 only** in this sample. No `.ogg/.m4b/.aac`, and **no m3u / m3u8 / HLS**
  playlist use was observed (grep over full raw HTML for `m3u8|m3u|ogg|m4b|aac|flac` → 0 hits;
  `*.mp3` → exactly 197 hits, one per track).

## 3. Download / anti-bot requirements

Tested with `curl` against `https://s1.knigavuhe.org/1/audio/285/<md5>/0001.mp3`:

| check | result |
|---|---|
| GET, no `Referer` | `206 Partial Content`, `Content-Type: audio/mpeg` |
| GET, with `Referer: https://knigavuhe.org/book/.../` | identical 206 |
| `HEAD`, no cookies | 200, `audio/mpeg` |
| `Range: bytes=0-1023` | 206 (byte ranges supported — good for resumable downloads) |
| URL with `?1` | 206 |
| URL with no query string | 206 |
| URL with bogus `?999` | 206 |

**Conclusion:** the audio CDN requires **nothing** — no cookie jar, no session, no Referer,
no `X-Requested-With`. The `?{v}` query is not an access token. MP3 magic bytes (`0xfffb`)
verify a real MPEG frame at offset 0.

### URL rotation caveat

Each `player_data` carries `"url_refresh":true, "url_refresh_at":<unix>, "url_refresh_in":<seconds>`
(`url_refresh_in` ≈ 221000 s ≈ **2.5 days** observed). This tells the in-browser player to
refresh the playlist URL after that window; the old URL may then stop resolving. So the
scraper **must not cache audio URLs long-term** — extract them from a fresh book-page fetch
right before downloading, and re-fetch the book page (retry) if a URL returns 403/404.

### Politeness

The upstream is a free, ad-supported site. The spike issues a small number of requests with
a 1 s delay between page fetches and retry-with-backoff. Production code should add a
User-Agent, throttling, and only fetch URLs it intends to download.

## 4. Recommended extraction strategy & parser choice

**No HTML parser dependency is required.** The audio payload is pure JSON text inside an
inline script, so the cleanest approach is:

1. GET the book page (the app's HTTP client).
2. Locate `new BookPlayer(` and run a small bracket-matcher over the `[ … ]` array
   (tracking string/escape state), or use a greedy regex
   `new BookPlayer\(\s*\d+\s*,(\[.*\])\s*\)` (DOTALL).
3. `json.loads(...)` the array — the `\/` escapes are valid JSON and parse directly.
4. Read each item's `url` (and `duration`, `title`); book id from the `BookPlayer(285,` arg
   or `cur.book`.

For the **search page**, the fields can likewise be pulled with targeted regexes on the
server-rendered `bookkitem` cards (see the spike script). If the production card parser needs
to be robust against markup churn (optional fields, multiple readers, highlighted keywords),
`selectolax` is the better fit than `bs4` (faster, CSS-selector friendly); but it is a
**nice-to-have, not a requirement** — regex + `json` fully covers the audio-extraction path.

### Recommended flow

```
search  -> GET /search/?q=<quote(query)>   -> first a.bookkitem_cover href = /book/<slug>/
book    -> GET /book/<slug>/                -> inline script new BookPlayer(id, [...])
audio   -> GET https://s1.knigavuhe.org/1/audio/<id>/<md5>/<NNNN>.mp3  (Range: bytes=… for resume)
```
